## 改用 StaticLayout 精确测量居中（解决换行导致高度不准）

- 问题：之前用逻辑行数 × fontHeight 估算高度，但歌词行换行后实际高度不等于行数 × fontHeight，导致居中偏移
- 修改文件：
  - `android/.../lyric/LyricView.java` — setLyric 方法重写 + gravity 改为 TOP
  - `android/.../lyric/LyricSwitchView.java` — 新增 setChildPadding 方法
- 新方案：
  1. 构建 SpannableStringBuilder 时记录当前行的字符偏移（currentLineStart/End）
  2. 用 `StaticLayout` 精确测量整个文本块的实际渲染高度（含换行）
  3. 通过 `getLineForOffset` 找到当前行在 StaticLayout 中的视觉行位置
  4. 计算 `currentLineCenter = (lineTop + lineBottom) / 2`（当前行实际像素中心）
  5. `paddingTop = viewCenter - currentLineCenter`（使当前行中心对齐窗口中心）
  6. 通过 `setChildPadding(0, paddingTop, 0, 0)` 设置子 TextView 的 top padding
  7. gravity 从 CENTER_VERTICAL 改为 TOP（由 padding 精确控制位置，不再依赖 gravity）
  8. 单行模式/回退路径统一 `setChildPadding(0, 0, 0, 0)` 重置 padding
- 构建 1 分 8 秒，BUILD SUCCESSFUL

## 改用 setScrollY 替代 padding 方案（解决当前行偏底部问题）

- 上一版 padding 方案问题：`setChildPadding` 改变了 TextView 内容区域宽度，导致 StaticLayout 测量宽度与实际渲染不一致；且 `StaticLayout` 构造函数默认 `BREAK_STRATEGY_SIMPLE` 与 TextView 的 `BREAK_STRATEGY_HIGH_QUALITY` 不一致
- 新方案改动：
  1. `LyricSwitchView`：移除 `setChildPadding`，新增 `setChildScrollY(int y)` 方法
  2. `LyricView.setLyric()`：用 `setScrollY()` 代替 `setPadding()` 定位当前行
     - `scrollY = currentLineCenter - viewCenter`（内容上移使当前行对齐窗口中心）
     - 在 `setText()` 之后调用 `setChildScrollY()`（因为 setText 可能重置 scroll）
  3. `StaticLayout` 改用 `Builder` 构建，设置 `BREAK_STRATEGY_HIGH_QUALITY` + `HYPHENATION_FREQUENCY_NORMAL` 匹配 TextView
  4. 单行/回退路径统一在 `setText()` 后 `setChildScrollY(0)`
- 优势：scrollY 不改变布局宽度，StaticLayout 测量与实际渲染宽度完全一致
- 构建 1 分 6 秒，BUILD SUCCESSFUL
